# v1.3 基础硬件层

## 统一端点

v1.3 将 SPP、BLE GATT 和 USB Host 收敛到 `PrinterConnectionService`。界面只提交 `DeviceCandidate + PrinterProfile + PrintJob`，不直接持有 Socket、GATT 或 USB Connection，因此离开界面不会立即中断正在发送的任务。

| 端点 | 发现 | 写入 | 回读 |
|---|---|---|---|
| 经典蓝牙 SPP | 已配对设备 | RFCOMM OutputStream 分包 | InputStream 常驻读取 |
| BLE GATT | 10 秒本机扫描 | 首选 UUID、能力回退、MTU 分包 | Notify/Indicate + CCCD |
| USB Host | Printer Class 或带 Bulk OUT 的接口 | 用户逐设备授权、claimInterface、Bulk OUT | 接口存在 Bulk IN 时常驻读取 |

USB Host 不是 USB Serial。只有暴露兼容 Bulk 端点并接受所选打印语言的设备才能工作；需要 CDC、CH340、FTDI 等串口驱动的设备仍需后续适配。

## 连接生命周期

- 用户确认蓝牙目标设备时即启动 `connectedDevice` 前台服务；首次连接失败也能继续后台重试。USB 必须先取得 Android 的逐设备授权，授权成功后再进入前台服务，避免违反 Android 14 的前台服务前置条件。
- 传输期间使用有超时上限的 partial wake lock，完成、失败或取消后释放。
- 非主动断开采用 1、2、4、8、16 秒指数退避；到 16 秒后保持该间隔无限重试，不存在次数上限。
- 已选端点、通道、档案和连接意图离线保存；服务进程恢复后继续连接同一设备，不重新猜测其它候选。
- 只有用户点击“断开”才清除连接意图、取消活动传输并停止无任务的前台服务。

## 任务可靠性语义

任务状态区分：排队、发送、已写入设备通道、设备确认、未确认完成、等待重试、失败、取消。

公开 ESC/POS、TSPL、CPCL、ZPL 原始通道通常只能确认字节写入，不能证明纸张已经物理打印。因此 v1.3 成功发送后标为“发送完成，设备未提供完成回执”，不虚报“打印成功”。十秒内相同内容使用 SHA-256 幂等键抑制重复点击。零字节进度的失败可自动重试；已经发送部分数据的任务为避免重复走纸，必须人工确认后重试。

## 状态探测

- ESC/POS：依次发送 `DLE EOT 1..4`，解析离线/忙、开盖、错误和纸张正常/将尽/用尽。
- ZPL：发送 `~HS`，解析缺纸、缺碳带、暂停、接收缓冲区、部分格式和打印头抬起。
- TSPL、CPCL：通用档案暂不主动发送未经逐型号确认的状态命令。
- 查询在 2.5 秒内没有回读时明确显示“端点不支持回读或设备故障”，不会把无响应解释为正常。

## 离线设备参数

每个内建档案可在 App 内调整并持久化：最大点宽、SPP/BLE/USB 分包、分包间隔、单包重试、二值化阈值、首选 BLE Service UUID 和 Write UUID。每个物理端点另行保存打印浓度、打印速度、纸张类型、间隙长度、自动出纸、提示音和自动关机时间，避免一台打印机的耗材参数污染另一台。

TSPL 编码会应用浓度、速度以及连续纸/GAP/BLINE 设置；ESC/POS 会应用自动出纸。提示音和自动关机属于厂商扩展，在缺少经型号验证的命令时只保存配置，不盲目向设备发送可能有副作用的命令。修改已选设备配置后，服务会按新档案重建连接，持续连接意图不被当作“手动断开”。

内建 BLE UUID 同时覆盖常见 FFE0/FF00/18F0 串流以及 Microchip Transparent UART：Service `49535343-FE7D-4AE5-8FA9-9FAFD205E455`、RX/写入 `49535343-8841-43F4-A8D4-ECBE34729BB3`、TX/通知 `49535343-1E4D-4BD9-BA61-23C647249616`。Transparent UART 只证明双向串流能力，不证明上层一定是打印协议，因此不会仅凭该 UUID 自动推断 ESC/POS。
