## 现场 BLE 端点

2026-08-16 扫描并连接到 `P1-0009200000`。用户提供的官方 App 设备详情确认其为德佟电子热敏标签打印机、203 DPI、384 点/48 mm；截图仍未证明其上层私有打印协议，因此只加入“已识别设备”，不加入“已认证打印协议”。

| 项目 | 观察结果 |
|---|---|
| 通道 | BLE GATT |
| Service | `49535343-FE7D-4AE5-8FA9-9FAFD205E455` |
| 写特征 | `49535343-8841-43F4-A8D4-ECBE34729BB3` |
| 通知特征 | `49535343-1E4D-4BD9-BA61-23C647249616` |
| 协商 MTU | 190 |
| GATT 串流连接 | 通过 |
| ESC/POS 状态探测写入 | 12 字节写入通过 |
| 状态回读 | 2.5 秒内 0 字节；端点未提供回读或上层协议不匹配 |
| 前台通知 | 正常显示连接状态 |
| 旧构建历史设备找回 | 旧构建曾在 5 秒内自动连接；当前构建已按新要求移除该行为，必须用户点选，待 ADB 恢复后复测 |
| 后台保持 | 返回桌面 12 秒后服务仍为 `isForeground=true`，连接通知仍显示该 BLE 端点 |

真机发送过程中发现三星系统会限制过高频率的通知更新。v1.3 随后将 UI 进度限制为约 10 次/秒、系统通知限制为约 2 次/秒，并增加纯 Java 队列测试。修正版已重新安装，连接、状态探测和后台保持期间未再出现通知限流；仍需在下一次经现场确认的完整大任务中复核高吞吐阶段。

横屏界面在同一台 SM-X800 上完成冷启动、UI 层级与截图检查。启动后活动保持前台，相机持续预览，日志中未出现 `FATAL EXCEPTION`、`SecurityException`、相机打开失败或布局 inflate 异常。未在竖屏上做同等级视觉调优；它仅作为系统忽略方向请求时的功能回退。

当前构建新增彩色连接状态徽标、设备/通道/地址详情、P1 制造商与规格、用户确认后连接、无限重连、按端点保存配置，以及轨道内二维码/条形码切换滑块。clean 构建、30 项 JVM 测试和 Lint 已通过；最终复核时 SM-X800 的 ADB 连接未恢复，因此这些新增交互（包括模式滑块）尚未在该平板上重复点击验收。
