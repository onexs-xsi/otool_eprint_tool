# v1.2 蓝牙实现

## 权限矩阵

| Android 版本 | 已配对 SPP | BLE 扫描/连接 |
|---|---|---|
| Android 12+ | `BLUETOOTH_CONNECT` | `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT` |
| Android 6–11 | 清单中的旧蓝牙权限 | 运行时精确位置权限（仅为旧系统 BLE 扫描要求） |
| Android 7 以下 | 不支持（应用最低 API 24） | 不支持 |

Android 12+ 的扫描权限声明使用 `neverForLocation`。应用不申请网络权限，也不上传扫描结果、MAC 地址或标签数据。

## 经典蓝牙 SPP

- 只列出 Android 系统已经配对的设备。
- 使用标准 SPP UUID `00001101-0000-1000-8000-00805F9B34FB`。
- 先尝试安全 RFCOMM，失败后再尝试不安全 RFCOMM 兼容旧机型。
- 安全和兼容 SPP 两次尝试各自最长等待 14 秒，并在连接前取消系统发现以降低干扰。
- 默认 1024 字节分包；每包刷新并按档案节流。

## BLE GATT

- 应用内低延迟扫描 10 秒，不要求预先配对。
- BLE 建链和服务发现整体设置 14 秒超时，避免系统 GATT 长时间停在连接中。
- 连接后发现服务，并优先匹配常见 `FFE0/FFE1`、`FF00/FF01/FF02`、`18F0/2AF1` 组合。
- 如果档案 UUID 未命中，会回退到第一个具备 `WRITE_NO_RESPONSE` 的特征，再回退到普通 `WRITE` 特征。
- 请求高连接优先级和 MTU 247；协商完成前按 20 字节有效载荷发送。
- 实际包长为 `min(档案包长, MTU - 3)`。
- `WRITE` 等待 GATT 回调，超时 5 秒；`WRITE_NO_RESPONSE` 使用节流，并对忙状态按档案次数重试。
- 诊断页显示当前通道、MTU、选中写特征、所有可写特征、最近字节数和最近错误。

## 状态与错误

```text
未连接
  → 正在连接
  → SPP 已连接 / BLE 服务发现
  → 已连接
  → 编码
  → 分包发送（进度）
  → 已发送 / 错误 / 已断开
```

“数据已发送”只表示 Android 传输层成功写出，不等同于打印机物理出纸成功。标准 SPP/BLE 打印机没有统一的纸尽、开盖或打印完成回执；此类状态必须由具体厂商协议或 SDK 扩展。

## 自动发现

“自动找打印机”会同时合并已配对 SPP 和附近 BLE，依据历史成功设备、名称族、蓝牙类别、Rendering Service、BLE 服务 UUID 与 RSSI 排序。发现阶段不会连接任何候选；无论可信度多高，都必须由用户点击设备并确认详情。完整评分规则见 `AUTO_PRINTER_DISCOVERY.md`。

## 现场排障顺序

1. 确认设备使用 SPP 还是 BLE；双模设备不要同时连接两个通道。
2. 确认打印语言，而不是只看设备名称。
3. 确认 DPI 和最大点宽；超宽任务会在应用内被阻止。
4. BLE 查看诊断中的写特征和 MTU；无可写特征通常表示设备并非串流打印服务。
5. 能写入但不出纸时，优先更换正确的协议档案。
6. 打印到一半断开时，降低档案包长或增加写入节流，再记录机型、固件和诊断信息。
