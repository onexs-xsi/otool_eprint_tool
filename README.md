# EPrint Android 打印上位机

EPrint 是面向 Android 设备的离线标签编辑与打印软件。当前主线为原生 Android，源码基线为 v1.5.41（本次只整理源码，不发布安装包）：

- 使用设备摄像头离线扫描二维码和常见一维条形码；
- “识别解析”按工作页提供扫描档位：普通页仅显示二维码/条形码，器件整理页显示并默认选择标签；各页选择独立持久化；
- 右侧“识别配置”覆盖标签、二维码、条形码的识别开关、制式、连续/反色/增强定位、GLM-OCR 后端与推理参数；标签页按流程、预处理、结果融合、GLM 实验/运行参数和 Qwen text-only 配置分组折叠，可记忆展开状态、批量展开/折叠并恢复推荐值；
- Qwen3.5-2B-MNN 已接入“拍摄识别”的 OCR 后处理阶段：固定模型 revision/全文件 SHA-256，拒绝图片与视觉 token，强制 `vision_time=0`；默认每次识别后实际运行并只补空字段，无 OCR 文字证据或目录校验失败的候选不会落盘，型号、料号和封装还必须有独立文字证据，失败时保留 PP/GLM 结果；识别配置可开启“修正明显错误”，仅在现值无证据、误取内部/订单编码或目录值非法且候选通过 OCR/格式/目录门禁时改写，该选项与“仅缺失时调用”互斥；同时可调整线程、Token、超时及额外文本规则；
- 器件整理提供简洁、标准、完整三档纯布局模板：分别采用紧凑、均衡、宽松的字号密度，模板不再绑定或限制字段；
- GLM-OCR 使用字段语义消歧的严格 JSON 提示词，并以同图 PP-OCR 逐行文本做视觉核对与字段落地校验，避免内部编码冒充型号、规格混入 ROHS、型号拆入参数；三档模板按需取字段；码区遮盖因实拍效果不稳定改为默认关闭的实验功能；
- 标签提取统一比较 Otsu、白卡、Canny 等真实四边形候选，以纸面/边缘/内容证据和冠亚军分差门控；胜出后用四条独立边线求交做透视精修，低置信度时无损回退；
- 真四边形拉正后可自动执行反光抑制：估计大尺度光照场、局部光照均衡并按收益门控，PP-OCR 与 GLM 共用同一优化图；识别结果可仅在电气单位后补空格，两项默认开启并可在识别配置关闭；
- 支持可选的立创品类、品牌和封装离线目录（公开源码不附目录快照，需自行确认数据使用权并本地导入）；PP-OCR 可规范品牌并按品类约束封装，双通道冲突时可选的目录强权重（默认开启）只保护可验证的品类/品牌/封装，不覆盖型号和规格；
- 三档器件模板分别记忆型号、品类、规格、封装、品牌、参数和立创料号的自由组合，切换布局不会重置或串改其他模板的字段；
- 固定前缀列和值列默认保留空字段以维持视觉对齐，也可开启“自动剔除空白项”在排版前删除空值行；识别底栏只显示最终完整结果，过程日志统一显示在右侧；
- 平板启动时优先进入横屏，主界面固定为左 1/3 扫码解析、右 2/3 打印机与标签画布；
- 左侧相机在识别过程中冻结并展示抓帧、真四边形矫正与实际 GLM 最终输入等阶段画面，全部流程结束后恢复实时预览；
- 在指定毫米尺寸和打印 DPI 的画布上添加、编辑、拖动文本；
- 通过经典蓝牙 SPP、BLE GATT 或 USB Host Bulk 发送打印任务；
- 支持 ESC/POS、TSPL/TSPL2、CPCL、ZPL 四类公开打印语言；
- 使用可离线保存的设备档案约束 DPI、有效点宽、传输分包、节流和 BLE UUID；
- 自动合并 USB、已配对 SPP 与附近 BLE，通过历史设备、USB Printer Class、名称族、蓝牙类别和服务 UUID 找出并排序候选；发现后必须由用户点击目标设备才连接；
- 使用 `connectedDevice` 前台服务保持用户选定的设备，支持 1/2/4/8/16 秒退避并持续重连，直到用户手动断开；
- 分开显示设备身份和协议档案，可识别德佟 P1 系列的制造商、203 DPI、384 点/48 mm，并按物理端点保存浓度、速度、纸张、间隙、自动出纸、提示音和关机时间；
- 已在 `P1-现场测试机` 上验证德佟私有协议的 BLE 基线、流控、打印前状态门控、完成回执轮询和连续 25 × 15 mm 标签打印；RLE、离线授权、电机/语言、任务变换及厂商信息解析属于默认关闭或尚待真机复验的扩展，不能据此外推其他机型；
- 通过 SPP 输入流、BLE Notify/Indicate 或 USB Bulk IN 回读 ESC/POS 与 ZPL 硬件状态。

应用清单不申请网络权限。二维码/条形码识别、文档保存、点阵渲染和打印编码均在设备本机完成。

## 本地构建

标准环境为 JDK 17+、Android SDK 36、NDK 27.3.13750724、CMake 3.22.1；Gradle Wrapper 固定为 8.14.3。无需维护者的 `.tools` 目录。从仓库根目录执行：

```powershell
& .\apps\android\gradlew.bat -p apps/android :app:testDebugUnitTest :app:lintDebug :app:externalNativeBuildDebug
```

完整安装、检查和自行构建步骤，以及可选 GLM/Qwen 模型与目录数据部署，见 [构建说明](docs/BUILDING.md)。本次不提供 APK 或 GitHub Release；可自行构建用于本机验证。

## v1.5 支持边界

经典蓝牙设备需先在 Android 系统设置完成配对；BLE 设备可在应用内扫描；USB 设备由 Android 系统逐设备授权。自动识别覆盖常见 POS58/POS80、TSC TSPL、Zebra CPCL/ZPL 名称族，未知设备必须手动确认档案。

主界面以横屏平板工作站为第一目标，Android 7–15 通过 `sensorLandscape` 自动使用当前横屏方向；API 36 同时声明大屏兼容模式。Android 17 起系统可能忽略方向限制，因此仍保留可运行的竖屏回退布局，但 v1.5 的首要验收基准是横屏 1:2 布局。

德佟 P1 私有协议目前只对现场设备 `P1-现场测试机` 的 203 DPI、384 点规格完成认证；P1 实打保护仍只允许现场已有的 25 × 15 mm 标签。其他固件、型号和纸张尺寸不能由该结果直接推定兼容。完整实测记录见 `docs/VALIDATION_V1.4.md`，通用设备边界见 `docs/PRINTER_COMPATIBILITY.md`。

兼容性统一按“编码已实现 / 通道已实现 / 真机已验证 / 实验性 / 未实现”分级。当前公开协议有编码与通用传输实现，但仓库内没有对应具体型号的实打认证；完整矩阵以 `docs/PRINTER_COMPATIBILITY.md` 为准。

网页方案已归档，不再参与主工程构建；后续开发请只在 `apps/android` 中进行。
